How should we find the tumor region?

The current CNN classifies Tumor/No Tumor — it doesn't know where the tumor is. We need a localization strategy to draw a contour and compute area.

A

GradCAM — Ask the existing CNN where it "looks"

Backpropagate gradients through the last conv layer to generate a heatmap showing which pixels influenced the Tumor prediction. Threshold the heatmap to produce a binary mask → contour.

Pros

  • Uses the model already in the project — no new model needed
  • Directly shows why the model said "Tumor"
  • Great pedagogical link between uncertainty (MC Dropout) and explainability (GradCAM)

Cons

  • Heatmap can be imprecise / blobby — not a sharp clinical contour
  • Requires gradient access (runs in train mode, which we already do for MC Dropout)
B

Image Processing — Threshold + Contour on the MRI

Convert to grayscale, apply Otsu's threshold or adaptive thresholding (OpenCV), find connected components, pick the largest bright/dark region as the tumor candidate.

Pros

  • No new model — pure OpenCV/PIL math
  • Produces clean, sharp contours
  • Works entirely in pixel space — natural fit for Monte Carlo area estimation

Cons

  • Threshold must be tuned; may fire on non-tumor bright regions (skull, etc.)
  • Not linked to the CNN's decision — separate pipeline
C

Combine Both — GradCAM mask guided by image intensity

Run GradCAM to get a rough attention region, then refine with Otsu thresholding only inside that region. Gives a model-grounded but geometrically clean contour.

Pros

  • Most accurate contour in practice
  • Keeps the story: model finds the region → math defines the boundary

Cons

  • More moving parts — two stages to tune and explain
  • Higher complexity for a demo feature
